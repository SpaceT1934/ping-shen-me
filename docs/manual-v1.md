# 手动 V1 业务规则

## 项目和目标

一个项目只显示一个当前目标，旧目标保留。项目可以编辑名称、结束、归档或恢复；归档不清除历史行动和报告。新增同名项目会提示修改名称。

目标支持数量、百分比和手动确认。数量目标使用整数；百分比目标固定上限 100；手动目标只有未完成和已完成。目标进度通过独立接口由用户明确更新；新增行动记录不携带贡献数量。任务完成和普通行动不自动推算业务目标进度。

替换进行中的目标时，旧目标归为历史；已完成目标不可修改进度。每个目标最多生成一个成果。

## 记录和任务

手动输入可按句号、分号和换行拆成确认卡片，用户自己选择分类与项目，这不是 AI 语义拆分。Action、Idea 可未归类，Task 必须属于项目；Goal 草稿保存为可未归类的目标建议记录，不会创建或替换正式目标。正式 Goal 必须通过项目详情明确创建。

记录保存实际发生日期，已发生的行动或灵感不允许未来日期。任务可填写未来计划日期。任务完成在同一事务中更新任务、创建行动和成长事件；撤销完成会撤销对应行动；重复完成或网络重试不增加第二条行动。任务生成的行动通过任务编辑或撤销来管理。

手动行动和灵感可编辑、重新分类、重新关联方向或删除。删除为软删除。修改会调整对应成长；旧版行动贡献保留在历史存储中；新记录不再携带贡献。已达成果保持达成时快照，不因后续纠错静默撤销。

一批确认卡片通过 `/record-batches/commit` 整体提交，任何条目失败则整批不保存；输入和草稿保留。提交期间按钮禁用；网络重试复用提交编号，超时和结果未知时保留原请求、幂等头及草稿，跨刷新重试沿用原请求。

## 成长

只有关联项目且有效的 Action 产生一次成长；Idea、Task、Goal 本身不成长，未归类 Action 关联后才成长。环境动效不代表业务成长。

暂定阶段集中在 `packages/domain/src/selectors.ts`，便于后续产品调整：

| 有效行动数 | 阶段     |
| ---------- | -------- |
| 0          | 刚种下   |
| 1 至 4     | 萌芽     |
| 5 至 11    | 枝叶舒展 |
| 12 及以上  | 茂盛     |

首页苹果大小和阶段标签随实际行动变化；项目超过四个时支持翻页。只有目标达成才显示成熟成果，成长次数本身不让目标自动完成。不因停止使用降低成长；用户纠错与删除会按真实数据重新计算。

## 成果

目标满足完成条件后，系统在事务中生成唯一 Result 并通知前端。统计采用该目标开始日至达成日内、该项目下的有效行动与灵感；天数从 Project 创建自然日到达成自然日，包含起止日且最少一天。

成果保存标题、行动数、灵感数和天数快照。收获可选择继续方向、准备新目标或结束项目。收获只更新成果的收获时间，不改变项目状态或当前目标；结束项目和创建新目标分别调用独立接口，设置新目标入口位于项目详情。收获历史成果不会覆盖已经切换的新目标。

## 报告

7 天和 30 天包含今天，本月按上海自然月，全部包含历史记录。行动次数按实际发生日期筛选，活跃项目为周期内至少存在一条有效行动的不同项目，新成果按达成时间统计，包括已成熟待收获成果。

进度条显示当前目标；报告不展示周期百分比增长，避免与当前目标进度混淆。归档和结束项目的历史数据保留。总结文案为基于统计的固定模板，没有 AI 调用。

## 尚未纳入

AI、语音识别、手机号和第三方登录、跨设备账号恢复、日签分享、通知和主题切换。备份当前支持 JSON 导出，尚无重新导入界面。成长阈值和纠错后成果保持快照为当前实现约定，可在下一次产品评审中调整。
