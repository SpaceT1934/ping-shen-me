# 苹什么：前后端接口约定 V0.2（实现版）

更新时间：2026-10-14。依据 V0.1 讨论草案修改，并与当前前端、后端和共享契约同步。

本版实现手机 Web 的手动记录流程，并新增 Python AI 分析与语音转写。账号登录暂未接入。AI 服务需要额外配置，未配置时手动业务仍可使用；AI 接口与扩展见第 9 节。

## 1. 地址、身份与通用响应

- 测试服务基础地址：`http://211.159.160.11:8105/api/v1`。
- 本地前端通过 `/api/v1` 代理访问后端；后端本地默认端口 3001。
- JSON 使用 UTF-8；所有 HTTP 请求和响应字段使用 `snake_case`。内部 TypeScript 对象的命名不属于对外接口。
- 首次调用 `POST /session`，后端创建或复用匿名会话，并设置 `apple_session` Cookie。后续请求带 Cookie；浏览器跨域请求需 `credentials: include`。
- Cookie 为 HttpOnly、SameSite=Lax，保留 180 天。当前 HTTP 测试入口未启用 Secure；HTTPS 环境启用 Secure。
- 正文不传 `user_id`。所有读写只访问当前会话所属数据；别人的项目、任务、目标或成果视为不存在。
- 业务对象 ID 为服务端生成的不透明字符串，不要求客户端解析 UUID。`client_item_id` 仅用于客户端条目对应，不是正式对象 ID。
- 时间是带时区的 ISO 8601，允许 `Z` 或 `+08:00` 等偏移；服务端生成的时间通常为 UTC `Z`。日期统计统一按 `Asia/Shanghai`。
- 空集合为 `[]`，无值为 `null`，数值为 JSON 数字。

成功（HTTP 200）：

```json
{
  "code": "OK",
  "data": {},
  "request_id": "req-1"
}
```

失败示例（HTTP 422）：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "请检查输入内容和日期",
  "details": [
    {
      "client_item_id": "i2",
      "field": "items.1.project_id",
      "message": "计划需要关联项目"
    }
  ],
  "request_id": "req-2"
}
```

`details` 按错误类型可省略；批量条目校验尽量携带 `client_item_id`。客户端按 `code` 处理，展示 `message` 和条目校验提示。每次请求拥有自己的 `request_id`，幂等重放时业务 `data` 不变，追踪编号可以变化。

| HTTP 状态 | 含义／常用 code                                                                                                    |
| --------- | ------------------------------------------------------------------------------------------------------------------ |
| 400       | 请求格式错误、缺少幂等头 `IDEMPOTENCY_KEY_REQUIRED`、无效游标 `INVALID_CURSOR`、业务操作不适用 `INVALID_OPERATION` |
| 401       | `UNAUTHORIZED`，会话失效，重新打开页面初始化会话                                                                   |
| 403       | `INVALID_ORIGIN`，写请求来源不允许                                                                                 |
| 404       | `NOT_FOUND`，对象不存在、不可访问或接口未实现                                                                      |
| 409       | `DUPLICATE_PROJECT`、`ACTIVE_GOAL_EXISTS`、`IDEMPOTENCY_CONFLICT`、`ENTITY_CONFLICT`、`IMPORT_CONFLICT`            |
| 422       | `VALIDATION_ERROR`，字段、条目关联或发生时间不合法                                                                 |
| 500       | `INTERNAL_ERROR`，服务端处理异常                                                                                   |
| 503       | `DATABASE_UNAVAILABLE`，就绪检查失败                                                                               |

AI 与转写接口按会话共享每分钟 10 次的限额，超限返回 `429 RATE_LIMITED`；其他业务接口尚无应用级限流。AI 未连接或不可用返回 `503 AI_UNAVAILABLE`，结果校验失败返回 `503 AI_PARSE_FAILED`，语音未开启返回 `503 ASR_NOT_CONFIGURED`。要求 AI 的部署就绪检查失败返回 `503 AI_NOT_READY`。

## 2. 分页与幂等

### 分页

列表接受 `cursor?`、`limit?`，默认 20、最大 100，返回：

```json
{
  "items": [],
  "next_cursor": null
}
```

`next_cursor=null` 表示结束。游标是不透明字符串；必须沿用相同列表和筛选条件，不跨接口或筛选复用。

项目、任务按 `created_at` 倒序；记录按 `occurred_at` 倒序；成果按 `completed_at` 倒序。同一时间再按 ID 倒序稳定排序。游标是位置分页，不提供跨多次读取的数据库快照；分页过程中如有新增记录，新内容可从第一页刷新读取。

### 幂等

所有持久化写入接口（除创建／复用会话外）携带 `Idempotency-Key`；AI 分析、转写和回顾生成不持久化业务数据，不要求此头。本版要求 1–200 个不含空格的可打印 ASCII 字符；建议使用随机 UUID。

```http
Idempotency-Key: 2f847c85-9e98-4da0-a1af-8149af1e470f
```

- 一个逻辑操作使用一个 key。自动重试、用户在结果未知时再次点击及刷新后的原请求重试，复用原 key、方法、路径和正文。
- 同一用户的 key 在所有写接口中共享命名空间。不要把同一个 key 用于创建项目和创建目标等不同操作。
- 成功请求持久化其业务响应；同 key 重放直接返回首次 `data`，不重新写入或重新计算成长。
- 同 key 配合不同操作或正文返回 409 `IDEMPOTENCY_CONFLICT`。
- 校验／业务失败不保存成功幂等记录。明确失败后修改输入，或者成功后发起新操作，使用新 key。
- 服务端数据库 `api_operations` 以 `(user_id, key)` 唯一约束保存成功结果，本版不按“最近 500 次”淘汰这些 HTTP 幂等记录。
- 同一事务内锁定用户花园、修改业务状态并保存幂等响应。批量操作全部成功或全部回滚。
- 数据库 `garden_entity_links` 另外保证每个任务只绑定一个完成行动、每个目标只绑定一个成果、每个行动只绑定一个成长事件。
- 客户端禁用按钮只是交互辅助，不能代替服务端幂等保障。

## 3. 对象结构

### Project

```json
{
  "id": "p1",
  "name": "学习英语",
  "status": "active",
  "goal": null,
  "growth": { "action_count": 0, "stage": 0, "stage_key": "stage_0" },
  "created_at": "2026-10-14T06:00:00.000Z",
  "icon": "book",
  "color": "blue"
}
```

`status=active/completed/archived`。`goal` 是当前目标，可为空；旧目标和成果仍保留。

展示扩展：`icon=mascot/apple/golden/green/video/book/work/calendar`，`color=sage/blue/peach/gold`。名称最多 100 字；同一用户的所有项目名称做 NFKC、首尾空白和大小写归一化后不能重复，包含结束／归档项目。单用户最多 200 个项目。

### Goal

字段：`id, project_id, title, mode, current_value, target_value, status, completed_at, created_at, unit`。

- `mode=count/percent/manual`；`status=active/completed`。
- count 的 `target_value` 是 1–1,000,000,000 的正整数，进度也是整数。
- percent 的 `target_value` 固定 100，进度允许小数。
- manual 的 `current_value` 和 `target_value` 返回 `null`；使用 `completed=true` 明确完成。
- 同时只能有一个活跃目标；已有活跃目标时创建接口返回 409，不覆盖它。
- 当前目标达成后可以显式创建下一目标；旧目标和成果不会删除。
- 标题最多 200 字，`unit` 最多 30 字；百分比单位返回 `%`。
- 已完成或历史归档目标不能通过进度接口修改。

### Task

字段：`id, project_id, content, status, due_at, completed_at, created_at, action_id`。

`status=pending/completed`；必须关联进行中项目；内容最多 200 字。`due_at` 可空、允许未来时间；`action_id` 是完成任务生成的行动 ID，未生成时为空。

### Record

字段：`id, project_id, type, content, source_text, source, emotion, occurred_at, created_at, source_task_id`。

- `type=action/idea/goal`，三种记录均允许未归类 `project_id=null`。
- `goal` 是目标建议，不是已经生效的 Goal。设置当前目标需要调用独立创建目标接口。
- `source=text/voice/task_complete`。本版没有语音上传／转写，`voice` 仅保留给已转写文本的来源标记。
- 内容 1–2000 字；`source_text` 和 `emotion` 可空，分别最多 10000 和 100 字。
- `occurred_at` 不能晚于服务器当前时间，未提供时使用保存时间。
- 任务生成的行动有 `source_task_id`；通过任务编辑／撤销管理，不能直接编辑或删除。
- 普通记录编辑、删除为显式纠错。未归类行动关联项目后补算该项目成长；移除关联、改为灵感／目标建议或软删除后调整成长。

### Growth

`action_count` 为关联项目的有效行动数，`stage` 为整数，`stage_key` 对应素材。服务端计算，客户端不能提交成长值。

| action_count | stage | stage_key | UI 阶段  |
| ------------ | ----- | --------- | -------- |
| 0            | 0     | stage_0   | 刚种下   |
| 1–4          | 1     | stage_1   | 萌芽     |
| 5–11         | 2     | stage_2   | 枝叶舒展 |
| ≥12          | 3     | stage_3   | 茂盛     |

阶段阈值为本版暂定配置，集中在领域层。任务、灵感、目标建议和情绪本身不产生成长。

### Result

字段：`id, project_id, goal_id, title, completed_at, harvested_at, days_to_complete, action_count, idea_count`。

每个目标最多一个成果。行动／灵感计数在达成时形成快照，统计该目标开始自然日至达成自然日内的项目有效记录；天数为项目创建日至目标达成日的上海自然日期差加 1，最少一天。后续纠错或新增行动不会改写旧成果快照。

项目批量创建示例：

```json
{

    { "client_item_id": "p1", "name": "学习英语", "icon": "book", "color": "blue" },
    { "client_item_id": "p2", "name": "规律运动" }

```

每批 1–50 项，`client_item_id` 在本批不能重复；图标默认 green、颜色默认 sage。默认只创建项目，首轮目标可通过独立接口设置。AI 引导扩展允许每项携带可选 `goal: {title,mode,target_value?,unit?}`，仅在用户确认后与新项目一起原子创建，失败整批回滚。创建成功会完成首次引导。

## 5. 确认保存

`POST /record-batches/commit`，携带 `Idempotency-Key`。

```json
{
  "raw_text": "今天剪了一条视频，明天背单词，还有个采访选题",
  "source": "text",
  "items": [
    {
      "client_item_id": "i1",
      "content": "剪了一条视频",
      "type": "action",
      "project_id": "p1",
      "emotion": null,
      "source_text": "今天剪了一条视频"
    },
    {
      "client_item_id": "i2",
      "content": "背单词",
      "type": "task",
      "project_id": "p2",
      "due_at": "2026-10-15T10:00:00+08:00"
    },
    { "client_item_id": "i3", "content": "采访选题", "type": "idea", "project_id": null },
    {
      "client_item_id": "i4",
      "content": "希望能完成一次公开演讲",
      "type": "goal",
      "project_id": null
    }
  ]
}
```

- `raw_text` 最多 10000 字，默认空字符串；`source=text/voice`，默认 text。
- items 1–50 项；每项 `client_item_id` 必填且本批唯一。
- 仅提交最终勾选条目；服务端不重新分类或改写内容。
- task 创建 Task，必须关联进行中项目；其他分类创建 Record，可不关联项目。
- 非空项目关联必须属于当前用户且进行中；无效关联返回带条目编号的 422。
- action/idea/goal 可传 `occurred_at`；task 可传 `due_at`。不要混用时间字段。
- `emotion`、`source_text` 未提供时为 null；任务日期未提供时为 null。
- 不接受客户端提交成长值、目标进度或贡献数量；更新目标进度使用独立接口。
- 整批在一个事务内完成。目标建议不会创建或替换正式目标。
- 完整原文只保存一次，并关联本批正式对象；普通列表不重复返回整批原文。

响应 data：

```json
{
  "batch_id": "b1",
  "saved_items": [
    { "client_item_id": "i1", "id": "r1", "type": "action", "project_id": "p1" },
    { "client_item_id": "i2", "id": "t1", "type": "task", "project_id": "p2" },
    { "client_item_id": "i3", "id": "r2", "type": "idea", "project_id": null },
    { "client_item_id": "i4", "id": "r3", "type": "goal", "project_id": null }
  ],
  "growth_changes": [
    {
      "project_id": "p1",
      "project_name": "自媒体",
      "action_delta": 1,
      "before": { "action_count": 0, "stage": 0, "stage_key": "stage_0" },
      "after": { "action_count": 1, "stage": 1, "stage_key": "stage_1" }
    }
  ],
  "completed_results": [],
  "feedback_text": "记录已保存，每一步都算数。"
}
```

同项目多条行动合并为一项 `growth_changes`，`action_delta` 累加，客户端播一次动画。普通记录保存和任务完成不推进目标，因此 `completed_results` 为空。没有成长变化时正常提示保存成功，跳过浇水页；固定鼓励文案不影响保存。

## 6. 任务、目标与收获

任务完成、生成唯一行动和成长更新处于同一事务。已完成任务使用新 key 再次 complete，返回同一行动和空变化数组；使用首次 key 重试，返回首次完整业务响应。

目标创建：

```json
{ "title": "发布 10 条视频", "mode": "count", "target_value": 10, "unit": "条" }
```

percent 可省略 target_value；如填写必须为 100。manual 不填 target_value。

进度更新示例：

```json
{ "current_value": 6 }
```

手动完成示例：

```json
{ "completed": true }
```

两种提交方式不能混用。数量／百分比达到上限后，系统在同一事务中标记完成并创建唯一 Result，`completed_results` 返回完整的新成果数组。未达成则为空。已完成目标不能倒退进度。

收获仅设置 `harvested_at`；不结束项目、不清空目标、不创建下个目标。客户端随后按用户选择：

- 继续记录：返回项目详情，无需额外写入。
- 结束项目：另发 `PATCH /projects/{id}`，正文 `{ "status": "completed" }`，使用新 key。
- 设置下一目标：进入目标编辑页，再调用创建目标接口，使用新 key。

收获和后续操作是独立事务；后续操作失败时，收获事实仍保留。客户端可重试失败的后续步骤，不重复收获成长或成果。

## 7. 报告

`GET /reports?range=7d`。

```json
{
  "range": "7d",
  "start_at": "2026-10-08T00:00:00+08:00",
  "end_at": "2026-10-15T00:00:00+08:00",
  "action_count": 12,
  "active_project_count": 2,
  "new_result_count": 1,
  "projects": [
    {
      "project_id": "p1",
      "project_name": "自媒体",
      "action_count": 8,
      "goal_progress": { "mode": "count", "current_value": 6, "target_value": 10 }
    }
  ],
  "summary": null,
  "recent_actions": []
}
```

- 7d 包含今天及前 6 个自然日；30d 包含今天及前 29 天；month 从本月 1 日开始；all 的 start_at=null。
- end_at 为明天上海时间 00:00，区间左闭右开。
- 行动按 occurred_at，成果按 completed_at 筛选；没有关联的行动计入总行动数，不计入活跃项目数。
- 归档和结束项目的历史记录及成果仍统计；报告 projects 包含历史项目。
- goal_progress 显示当前目标进度，不能解释为本周期增长。没有当前目标时为空；manual 数值为空。
- `recent_actions` 是本版展示扩展，最多 3 条完整 Record；它的条数不是总行动数。
- `summary` 固定为 null；按需生成的 AI 总结使用第 9 节的独立接口，数字以本接口统计为准。

## 8. 保留现有功能的扩展接口

| 方法与路径                | 请求／响应                                                              | 说明                                                                                                         |
| ------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| PATCH `/onboarding`       | `{onboarding_completed:true}` → bootstrap 结构                          | 开始页“看看我的树”                                                                                           |
| GET `/tasks`              | 分页 Task                                                               | 当前用户全部项目任务，避免逐项目请求                                                                         |

| DELETE `/tasks/{id}`      | → `{deleted:true}`                                                      | 软删除未完成任务；已完成任务先撤销                                                                           |
| PATCH `/records/{id}`     | `{content?,type?,project_id?,occurred_at?}` → `{record,growth_changes}` | 编辑普通行动／灵感／目标建议；至少一项                                                                       |
| DELETE `/records/{id}`    | → `{deleted:true,growth_changes}`                                       | 软删除普通记录；任务行动通过 reopen 管理                                                                     |
| GET `/exports/garden`     | 完整 snake_case 备份对象，`schema_version=2`                            | 包含历史目标、记录、任务、成果和事件，内部 operations 导出为空；结构是备份格式，不是列表 DTO；不支持重新导入 |
| POST `/imports/legacy`    | `{legacy,onboarding_completed}` → bootstrap 结构                        | 仅空花园可导入旧浏览器原型一次                                                                               |
| GET `/health`             | `{status:"ok",service:"apple-api"}`                                     | 无需会话                                                                                                     |
| GET `/health/ready`       | `{status:"ok",database:"connected",driver}`                             | 无需会话；失败 503                                                                                           |

扩展写接口同样需要幂等头。记录纠错可能返回负 `action_delta`；客户端更新展示，不播放成功浇水动画。已达成果快照不会因纠错静默撤销。旧版行动贡献值仍保留在历史存储中，本版新增记录不再接受贡献数量。

旧原型导入的 legacy 对象为 `{projects,tasks,entries}`：projects 保留旧版 `id,name,goal,target,progress,icon,color,harvested`；tasks 为 `id,project_id,title,when,done`；entries 为 `id,project_id,content,type,date,task_id?`。该入口只用于既有浏览器缓存迁移，不用于普通业务保存，也不能覆盖非空花园。

本版不再公开 `GET /garden` 或 `POST /garden/commands`。前端通过资源接口读取数据，写入成功后重新读取受影响资源并更新共享缓存。

## 9. AI 与语音接入

已验证：创建／读取项目 → 手动确认行动、任务、灵感和目标建议 → 保存 → 只有关联行动触发成长 → 同 key 重试不重复写入 → 任务完成不重复行动 → 独立完成目标生成成果 → 收获不改项目状态 → 分页 → 报告 → 数据库重启后幂等结果保留 → 用户间隔离。

以下路径均以 `/api/v1` 为前缀，要求已有匿名会话，沿用本版响应信封与 snake_case。手动 commit 不要求先调用 AI。

| 接口                         | 请求                                                 | data                                                                     |
| ---------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------ |
| GET `/ai/capabilities`       | 无                                                   | `{ai_configured,asr_enabled}`                                            |
| POST `/ai/projects/analyze`  | `{text}`，1–300 字                                   | `{candidates:[{name,goal_text,source_text}]}`                            |
| POST `/ai/records/analyze`   | `{text,source?}`，1–2000 字；source 为 text 或 voice | `{items:[{client_item_id,content,type,project_id,emotion,source_text}]}` |
| POST `/ai/reports/summarize` | `{period}`，7天、30天、本月、全部                    | `{summary}`                                                              |
| POST `/asr/transcribe`       | `{audio_base64,mime_type}`，原音频不超过 5 MB        | `{text}`                                                                 |

Node 只提供当前会话所属的活跃项目给 Python，未知项目 ID 清空为 null；AI 返回的 source_text 必须是输入原文的连续片段。草稿必须经网页编辑、确认后调用批量保存接口。goal 类型草稿是普通目标建议记录，不创建或替换正式目标，不改变目标进度。

音频支持 WAV、MP3、WebM、Ogg、FLAC；不把原音频保存进业务数据库。浏览器录音最长 60 秒，公网录音需要 HTTPS。转写和文字分析是两次独立请求，转写后可先改文字。模型失败不自动重试。回顾只读后端统计，同会话、数据版本、周期缓存 10 分钟；空报告不调用模型。
