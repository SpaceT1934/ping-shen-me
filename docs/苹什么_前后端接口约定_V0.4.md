# 苹什么：前后端接口约定 V0.4（PRD V1.1 对齐版）

更新：2026-10-18。对应手机 Web、水彩手帐风小树林、多目标、确认贡献、手动收获和按收获数升级。V0.2、V0.3 留作历史版本，当前以本文和 packages/contracts/src 为准。

## 通用约定

- 公网基础地址：`https://211.159.160.11:8105/api/v1`。本地前端同源 `/api/v1` 代理至 API。
- 首次 `POST /session`，后续携带 `apple_session` Cookie。匿名会话 180 天，HttpOnly、SameSite=Lax，公网 Secure。尚无跨设备账号恢复。
- 所有对象归属来自会话，正文不接受 user_id。跨站写检查 Origin。
- HTTP 字段 snake_case；时间为带时区 ISO 8601；日期统计统一 Asia/Shanghai。ID 为不透明字符串。
- 成功 HTTP 200：`{code:"OK",data:...,request_id:"..."}`；失败：`{code,message,details?,request_id}`。校验通常 422，领域规则 400，未登录 401，资源不存在 404，幂等/版本冲突 409。
- 所有业务写接口使用 `Idempotency-Key`。同会话同 key 同路径同正文重试返回首次结果；复用 key 改请求为 409。一个批次原子提交；并发写入由数据库事务串行化。
- 分页接口返回 `{items,next_cursor}`；limit 默认 30、最大 100，cursor 仅可用于原筛选。项目上限 200，目标累计上限 2000，批次 1–50 条。

## Project、Goal 和 Growth

Project 返回 `id,name,status,category?,goal,goals,growth,created_at,icon,color`。

- status：active / completed / paused / archived；名称最多 200 字，同一用户内归一化后唯一。
- `goals`：这个项目所有未归档 Goal，包含已达成目标。
- `goal`：主要 Goal，兼容 V0.2。多个目标可并行进行；新增不会替换旧目标。主要目标达成且还有进行中目标时自动选下一个。
- `icon`：mascot/apple/golden/green/video/book/work/calendar；`color`：sage/blue/peach/gold。

Goal：`id,project_id,title,mode,current_value,target_value,status,completed_at,created_at,unit`。

- mode 为 count / percent / manual，status 为 active / completed。
- count：正整数 target_value，整数进度；percent：target_value 固定 100，进度可为小数。
- manual：两个数值字段均 null，使用 completed=true 确认达成。
- 标题最多 200 字，unit 最多 30 字。进度超过上限截断；已完成 Goal 不可倒退。每个 Goal 最多一个 Result。
- UI 五档果实：0 小青果，(0,30]% 青果，(30,60]% 青黄果，(60,100)% 青红果，100% 红果成熟。

Growth 示例：

```json
{
  "action_count": 8,
  "harvest_count": 3,
  "tree_stage_threshold": 3,
  "stage": 1,
  "stage_key": "stage_1"
}
```

`action_count` 只统计有效关联 Action，用于浇水反馈。`harvest_count` 只统计本项目已手动收获的不同 Goal。`stage=min(3,floor(harvest_count/K))`，K 为 tree_stage_threshold，支持 1、2 或 3，新版默认 3。客户端不能直接提交 stage 或计数。

| 默认收获数 | API stage | 产品阶段 | 名称     |
| ---------- | --------- | -------- | -------- |
| 0–2        | 0         | 1        | 树苗期   |
| 3–5        | 1         | 2        | 成长中   |
| 6–8        | 2         | 3        | 茁壮成长 |
| 9+         | 3         | 4        | 硕果累累 |

## 行动保存与目标贡献

```json
{
  "raw_text": "今天剪完视频，还发布了一条视频。",
  "source": "text",
  "items": [
    {
      "client_item_id": "i1",
      "content": "剪完视频",
      "type": "action",
      "project_id": "p1",
      "goal_id": "g1",
      "contribution": 0
    },
    {
      "client_item_id": "i2",
      "content": "发布一条视频",
      "type": "action",
      "project_id": "p1",
      "goal_id": "g1",
      "contribution": 1,
      "progress_confirmed": true
    }
  ]
}
```

- source 为 text 或 voice，默认 text；raw_text 最多 10000 字。
- 每项必填 client_item_id/content/type/project_id；type 为 action/task/idea/goal。内容 1–2000 字，Task 最多 200 字且必须关联项目。Idea 和 Goal 是建议记录，不创建正式目标。
- 可选 source_text/emotion/occurred_at/due_at 沿用 V0.2；已发生记录不能填未来时间，Task 用 due_at，不与 occurred_at 混用。
- 新增 goal_id（默认 null）、contribution（默认 0）、progress_confirmed（默认 false）。只有 Action 可关联自己项目的进行中 Goal。
- 正数贡献必须同时有 goal_id 和 progress_confirmed=true。count 贡献为整数，percent 为增量百分点；manual 不接受数量贡献，改用独立进度接口。
- 关联 Goal 不表示对指标有贡献。剪辑与发布不同，AI 不会自动填贡献。前端只有用户明确填写正数并确认保存才传确认标记。
- 持久化 Record 新增 goal_id、contribution；progress_confirmed 为请求确认标记，不是可编辑进度字段。
- `growth_changes` 按项目合并，字段仍为 project_id/project_name/action_delta/before/after。普通行动增加 action_count，但不改变树阶段。
- 明确贡献可在本次事务达到目标上限；此时 completed_results 返回新建的待摘 Result。无新成熟 Goal 时为空。只有关联项目的有效 Action 播放浇水。
- 只改文案和日期保留已确认贡献；改变分类/项目或删除，撤回尚未完成 Goal 的原贡献。已达成果为事实快照，不静默撤销。任务生成行动通过撤销任务完成管理。

## 手动收获与报告

Result：`id,project_id,goal_id,title,completed_at,harvested_at,days_to_complete,action_count,idea_count`。

目标 100% 只设 completed_at 并创建 Result，harvested_at=null，果实仍留在树上。只有 POST harvest 成功才设 harvested_at，纳入这个项目的果篮并参与升级。不同请求或并发重复摘同一果实均只计一次；未成熟 Goal 没有可摘 Result。

相关 action_count 仅统计明确关联此 Goal 的有效行动。idea_count 为目标期间项目内灵感；天数从 Goal 开始自然日至达成日，包含起止日、最少一天。旧版已经产生的快照原样保留。

摘果不自动结束项目或创建新目标；前端按选择另行 PATCH 项目状态或进入目标添加界面，各请求使用独立幂等 key。果篮只含 harvested_at 非空的成果，待摘列表独立展示。

Reports 返回 range/start_at/end_at/action_count/active_project_count/new_result_count/projects/summary/recent_actions。projects 含 project_id/project_name/action_count/goal_progress，goal_progress 为主要目标的 mode/current_value/target_value；recent_actions 为最近三条记录。新成果按达成时间计算，可包含未收获果实，与树阶段收获数不同。7 天和 30 天包含今天，本月用上海自然月，归档历史保留。

## AI 与语音（只读草稿）

| 接口                         | 请求                           | data                                                                             |
| ---------------------------- | ------------------------------ | -------------------------------------------------------------------------------- |
| GET `/ai/capabilities`       | 无                             | `{ai_configured,asr_enabled}`                                                    |
| POST `/ai/projects/analyze`  | `{text}`，1–300 字             | `{candidates:[{name,goal_text,source_text}]}`                                    |
| POST `/ai/records/analyze`   | `{text,source?}`，1–2000 字    | `{items:[{client_item_id,content,type,project_id,goal_id,emotion,source_text}]}` |
| POST `/ai/feedback`          | `{}`                           | `{text}`，最多 60 字，已保存行动的短反馈                                         |
| POST `/ai/reports/summarize` | `{period}`，7天/30天/本月/全部 | `{summary}`，最多 240 字                                                         |
| POST `/asr/transcribe`       | `{audio_base64,mime_type}`     | `{text}`                                                                         |

Node 仅提供当前用户项目及进行中目标给 Python，未知项目或跨项目 goal_id 清空。source_text 必须是原文连续片段。分析不写库，不新增项目、不改进度；确认保存才调用业务接口。失败保留原文，可手动修改归属和贡献。

短反馈基于服务端最近有效行动生成，按用户和数据版本缓存 10 分钟，不阻塞保存或跳转；模型异常回退固定温和文案，不宣称成熟或升级。报告基于实际统计，不凭空构造数据。

浏览器点击录音、停止后转写，最长 60 秒，公网要求 HTTPS。支持 WAV/MP3/WebM/Ogg/FLAC，原音频不超过 5 MiB，不入业务数据库。转写后可修改文字，再分析、确认；模型失败不自动重试。密钥仅存在服务端私有配置。

## 兼容与验收

旧会话、项目、目标、记录和收获历史保留；没有 treeStageThreshold 的旧快照默认 3。新增事实继续保存在既有事务聚合中，无清库、无自动补摘果。旧 goal 字段保留，新增 goals 数组。

验收覆盖：多个目标独立进度；未确认不写库；零贡献不推进；跨项目关联拒绝；成熟不自动收获；同 key 重试和并发收获唯一；每树独立阈值、四阶段上限；刷新及数据库重启后数据保留。

## Figma 21 同步扩展（2026-10-18）

- 项目状态新增 `paused`（暂缓）。暂缓项目保留数据，恢复 active 后才允许继续记录和完成任务。旧 archived 状态继续可访问。
- 项目名称上限改为 200 字；`tree_stage_threshold` 支持 1/2/3，没有显式配置时使用 3。已有显式 1/2 的配置保留。阶段名称为树苗期、成长中、茁壮成长、硕果累累。
- `POST /ai/projects/analyze` 的 candidates 新增 `category`，枚举为工作事业、学习成长、健康运动、生活习惯、兴趣爱好、其他。旧 AI 响应缺省为其他，前端允许修改；不输出虚构置信度。
- 新增 `POST /ai/tasks/plan`：请求 `{project_id,text}`，text 为 1–200 字；只允许当前用户自己的 active 项目。成功 data 为 `{tasks:[{title,description}]}`，1–6 项，title 1–80 字，description 1–110 字。
- 任务规划只返回草稿，不修改项目、任务或进度。确认后使用现有 `/record-batches/commit`，每项 type=task，整体事务和 Idempotency-Key 重试规则不变。非法项目 404，输入不合法 422，模型不可用或输出校验失败 503，超额 429。
- 报告页面的四项指标与同比由已有记录、成果和目标计算；熟果收获与趋势按 `harvested_at` 统计，完成目标按 `completed_at` 统计。不存在上期数据时显示“本期新增”，不制造百分比。原报告 API 字段含义不变。
- 昵称、主题、动效、音效、小树测试、日签制作标记和提醒偏好保存在当前浏览器；此版本没有新增账号同步接口。提醒只在网页打开时检查，关闭网页后的后台推送尚未实现。通知权限由用户点击后向浏览器申请，拒绝后仍提供页面内提醒。

项目创建条目和 PATCH 新增可选 `category`（1–20 字，支持自定义），随项目保存在服务端并在列表、详情、导出中返回；旧项目缺省时兼容浏览器旧分类或按图标提供初始分类。
